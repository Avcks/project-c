Good practices found

Critical

Passwords stored in plain text — customers[].cPass is stored as raw text in the .dat file and even printed in viewCustomers(). Anyone with file access can read all passwords.
Hardcoded admin/staff credentials — ad_user="admin", ad_pass="admin" in global variables. Trivially guessable and can't be changed without recompiling.
Buffer overflow risk in scanf — scanf("%s", ...) used without width limits on many string reads (e.g. product name, customer name). Overlong input will overwrite adjacent memory.
Unbounded recursion for navigation — menus call themselves recursively on bad input (e.g. adminDashboard() calling itself). With enough navigation steps, the stack will overflow.

Warnings

Windows-only — uses <windows.h>, <conio.h>, system("cls"), system("pause"). Will not compile or run on Linux/macOS.
No numeric input validation — entering a letter where a number is expected leaves garbage in the input buffer and corrupts subsequent scanf reads.
Cart not cleared on logout — cartCount is reset after checkout, but if the customer logs out without checking out, cart items persist to the next session.
Real UPI ID hardcoded — 6353999107@ptyes is embedded directly in source. Fine for a project, not for production.
Sales log silently drops records — once nSales == MAX_SALES (1000), recordSale() silently drops all new transactions with no warning.

Good practices

Duplicate product code and customer ID checks before insertion
Password confirmation on customer account creation
Stock deducted and persisted immediately on cart add
Full saveAllData() call on checkout ensures no data loss
All forward declarations at top — clean compilation order

Security fixes (high priority)

Hash passwords — use a hash (e.g. djb2 or SHA-256) before storing. Never write raw passwords to disk or display them on screen.
Protect admin credentials — read them from a config file or environment variable, not hardcoded in source. Apply the same hashing.
Limit scanf widths — change scanf("%s", name) to scanf("%49s", name) to match the buffer size. Apply consistently to all string inputs.

Code quality improvements

Replace recursion with loops — convert all menu functions to use a while(1) loop with a break on exit, instead of calling themselves.
Clear cart on logout — add cartCount = 0; in the customer logout path inside cust(), not only after checkout.
Validate numeric input — check scanf's return value and call while(getchar()!='\n'); to flush the buffer on bad input.
Remove duplicate code — custManage() and the case-7 block inside staff() are nearly identical. Extract into one shared function.

Feature enhancements

Sales log rotation — when nSales hits the limit, archive old records to a separate file rather than dropping them silently.
Product search by name — currently customers can only search by product code; a name-based search would be more natural.
Itemised receipt — after checkout, print product names, quantities, unit prices, discount applied, and a transaction ID.
Portability — replace system("cls") with printf("\033[2J\033[H") and system("pause") with a getchar() loop to support Linux/macOS.
