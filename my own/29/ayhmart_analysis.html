System Overview

AYH Mart is a comprehensive, terminal-based Point of Sale (POS) and Self-Checkout System written in C. It is designed to simulate a modern retail environment, featuring robust user authentication, inventory management, dynamic customer membership tiers, and a seamless self-checkout process with simulated QR digital payments.

C Language File I/O Structs CLI Interface Access Control

Key Capabilities

  • Multi-Role Access Control: Distinct portals for Admin (full access), Staff (inventory/member viewing), and Customers (self-checkout).
  • Dynamic Inventory & Categories: Products can be added, edited, deleted, and categorized. Validation ensures unique product codes and names.
  • Membership Tiers: Customers can be upgraded to Members with tiers (Silver 5%, Gold 10%, Platinum 15% discount).
  • Self-Checkout System: Customers can browse items, search via code, add to basket, and checkout using Cash or simulated Digital/QR payment methods.
  • Data Persistence: All system state (Products, Members, Customers, Sales, Categories, Counters) is serialized and stored in binary .dat files.
  • Backup & Restore: Built-in functionality for administrators to snapshot the current state and restore it.

Code Quality & Observations

1. Strengths

  • Modular Design: The code is well-structured into distinct functions (adminDashboard(), cust(), staff(), etc.), making it highly readable and maintainable.
  • Input Masking: Includes a custom inputPassword() function utilizing getch() to hide user passwords behind asterisks (*).
  • ANSI Color Formatting: Uses ANSI escape codes (e.g., \x1b[32m) to provide a visually engaging and color-coded terminal experience.
  • Safety Checks: Robust existence checks (e.g., isProductCodeExists()) and bounds checking (nProducts >= MAX_ITEMS) prevent buffer overflows and duplicate data.

2. Areas for Enhancement

  • Security: Admin and Staff credentials are hardcoded as plain text strings. Moving these to a configuration file or a secured binary file would improve security.
  • Memory Optimization: The program currently uses globally declared, fixed-size arrays (e.g., MAX_SALES 1000). Implementing dynamic memory allocation (malloc/realloc) would allow for infinite scaling and reduce baseline memory footprint.
  • File Locking: The backup and save mechanisms directly overwrite .dat files without temporary swap files, which could risk data corruption in the event of a sudden crash during write operations.
